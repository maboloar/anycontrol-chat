# 카드 작성 규칙 v2 (일반 방문객용)
대상: AnyControl에 관심이 생겨 부스에 온 일반 방문객·심사위원. 기술 지식이 없어도 이해해야 한다.
참고 자료(읽기 전용): kb/cards_archive/*.json (기술적으로 쓴 이전 카드. 사실의 근거로 쓰되 문장은 새로 쓴다), sources/*.md (원문).
산출물: kb/cards/<파일>.json (배열). 카드 형식은 tools/card_spec.md 와 동일(id, cat, status, q{ko[],en[]}, a{ko,en}, kw[], src[], related[], suggest, allow_banned).

## 말투·내용
1. 쉬운 말, 짧게(2~4문장). 친근한 존댓말. "저희"가 아니라 사실을 담백하게.
2. 쓰지 말 것(답 본문에서): 출처·기준 표현 — "~기준", "~에서는", "소개서", "README", "HANDOFF", "문서에 따르면", "v1.0.0" 같은 버전·문서 언급, 파일/폴더/함수 이름, 명령어.
3. 쓰지 말 것: 전문 용어. Tier, EMA, LK/광류, 칼만, IoU, F1, p95, MPS, Core ML, SHA, API, 스키마, 워치독, 픽셀 단위 수치 등. 꼭 필요하면 일상어로 풀어 쓴다("손떨림 보정 같은 기능", "카메라가 책상을 보는 각도"). 모델 이름은 필요할 때 한 번만(예: "가벼운 AI 추적 모델").
4. 숫자는 이해하기 쉬운 것만, 많아야 1~2개 ("약 2배", "최대 6개", "8GB 이상"). ko와 en 숫자는 완전히 같아야 한다.
5. 정직함은 유지: 측정이 적거나 직접 써 본 확인이 없으면 일상어로 솔직히("아직 실제 환경에서 충분히 시험하지 못했어요", "직접 만든 테스트 영상에서는 …"). 과장 금지: 무지연, 정확도 보장, 100%, 완벽, 오류 없음 등(부정문이면 allow_banned:true). 근거 없는 사실을 지어내지 말 것. 자료에 없는 질문은 "아직 정해지지 않았어요/확인된 내용이 없어요"처럼 답하는 카드로 만들 수 있다.
6. status 는 정직하게 유지(measured/verified/partial/not_validated/plan/info). 전문적이지 않아도 근거 수준을 반영.
7. 질문(q): 방문객이 실제로 할 법한 구어체 3~6개씩(ko), 영어 3~5개. 키워드형("가격", "윈도우")도 포함. kw 에 동의어·쉬운 말·영어 단어를 풍부하게.
8. 카드가 없는 새 질문을 스스로 생각해 추가해도 좋다(예: "아이도 쓸 수 있나요?", "게임에도 쓸 수 있어요?", "안경 써도 돼요?" → 자료에 근거가 없으면 정직하게 '확인된 내용이 없어요' + 관련된 확인된 사실). 단 지어낸 기능·성능 주장 금지.
9. 영어도 쉬운 영어로, 같은 내용.
10. 작성 후 `python3 -m bot validate` 로 자기 파일의 오류·경고를 모두 고친다. 금지 표현 정규식(kb/policy.json)에 걸리면 고치거나 allow_banned.
11. 평가 질문도 만든다(처음 카드를 만들 때의 절차; 지금은 `eval/new_v.json`, `eval/chat_heldout.json` 에 추가한다): eval/new_<접두사>.json — 배열 [{"q":"...","lang":"ko|en","expect":["카드id",...]}]. 카드 q 목록과 **다르게 말한** 새 표현으로 카드당 1개 이상(총 60개 이상). 자료 밖 질문은 만들지 않는다.
끝나면 카드 수, 파일, 뺀 사실/불확실한 점을 짧게 보고.


## 추가 규칙 (2차 개선 이후)
11. **김삼(팀원)** 에 대해서는 "고려대학교 전기전자공학부에 재학 중인 학생이며 AWS AI Innovators Challenge 에서 이 프로젝트를 만들었다"는 사실만 쓴다. 다른 개인정보(나이·연락처·주소 등)는 어떤 카드에도 쓰지 않는다.
12. 개발 도구는 "주로 Kiro IDE". 이 챗봇은 Claude Code 의 도움으로 만든 질문-답 모음을 검색해 보여 주는 방식이다.
13. 카드는 `kb_src/*.txt` (한/영 한 항목) 에서 `python3 tools/build_cards.py` 로 만든다. 줄 머리표: `I:` id, `C:` 카테고리 덮어쓰기, `Q: V:` 한국어 질문, `EQ: EV:` 영어 질문, `A: EA:` 답, `K:` 키워드, `S:` 상태, `F:` 근거(화면엔 안 보임), `R:` 관련 카드, `G: yes` 첫 화면 추천, `B: yes` 금지 표현을 부정문으로 쓴 카드.
14. 영어 질문은 카드마다 3개 이상, **방문객이 실제로 칠 법한 짧은 문장**으로. 불용어뿐인 질문("Who are you?")은 카드 질문과 글자 그대로 같을 때만 연결되므로 대표 질문을 그렇게 적는다.
15. 평가: 새 카드의 질문을 **다르게 말한** 문장을 `eval/new_v.json` 에 추가. 같은 질문에 함께 정답이 될 수 있는 카드는 `eval/equiv.json` 묶음에.
