# 펜–책상 접촉 판별: 라벨 없이, 영상만으로, 실시간

> 이 문서는 **다른 AI(또는 개발자)가 이 코드를 처음 보고도 설계 의도, 수식, 파라미터, 검증 결과, 한계를 그대로 이어받을 수 있도록** 쓴 기술 문서입니다.
> 코드: `table_model.py`, `contact_detector.py` (본체) / `demo_pen_segmenter.py` (테스트용 대체 분할기) / `run_video.py`, `evaluate.py`, `ablation.py` (실행·검증)

---

## 0. 한 줄 요약

**"펜은 책상을 뚫고 내려갈 수 없다"** 는 물리 제약을 이용해, 펜 끝의 화면 위치(`d`)와 펜 몸통의 화면 굵기(`w`)가 접촉 순간 만족하는 직선 관계 `d = k·w − c` 를 **영상 스트림에서 스스로 학습(라벨 없음)** 하고, 그 직선으로부터 펜 끝이 얼마나 떠 있는지(펜 지름 단위)를 매 프레임 계산한다. 직사광이 있으면 **그림자–펜끝 접합** 단서로 보강하고, **히스테리시스 상태기계**로 시간적으로 안정화한다.

## 1. 문제 설정과 제약

| 항목 | 내용 |
|---|---|
| 입력 | 고정 카메라 1대의 실시간 영상(테스트: iPhone, 1920×1080, 60 fps) + 매 프레임 펜 분할 마스크(사용자가 이미 보유) |
| 출력 | 매 프레임 `contact ∈ {True, False}` (+ 디버그 값) |
| 금지 | IR LED·레이저·마이크 등 추가 하드웨어, **학습용 라벨링** |
| 요구 | 실시간(인과적: 과거 프레임만 사용), 정확한 터치다운/리프트오프 시점 |

### 1.1 테스트 영상(`pen_test.mov`)에서 관찰한 사실 — 설계의 출발점
1. **카메라가 거의 책상 높이(그레이징 앵글)** 에 있다. 책상은 화면 하단의 띠로 보이고, 책상 먼 쪽 모서리(far edge)가 거의 수평선 근처에 있다.
2. **직사광(햇빛)** 이 들어와 손·펜의 그림자가 길고 선명하다.
3. **책상이 약간 광택** 이 있어 그늘 영역에서 셔츠/펜이 거울처럼 비친다 → 분할기가 **반사상을 펜으로 오인**하는 경우가 생긴다.
4. **카메라가 천천히 기울어진다**: 10초 동안 책상 모서리가 화면에서 약 45 px 아래로 이동 → 고정 캘리브레이션은 쓸 수 없다.
5. 펜 끝(닙)은 어둡고 가운데 구멍이 있으며, 펜 아랫면은 책상 반사광 때문에 따뜻한 색을 띤다 → 색 기반 분할이 닙/아랫면을 자주 놓친다.

### 1.2 왜 어려운가 (핵심)
단안 카메라에서 펜 끝의 화면 y좌표만으로는 **깊이 모호성** 때문에 접촉을 알 수 없다. "가까이서 3 mm 떠 있는 펜 끝"과 "조금 멀리서 닿아 있는 펜 끝"이 같은 화면 위치에 찍힌다. 따라서 **깊이를 알려주는 두 번째 측정값**이 필요하다 → 여기서는 **펜 몸통 굵기 `w`** (펜 지름이 고정이므로 `w ∝ 1/깊이`).

## 2. 전체 파이프라인

```
frame ──► TableModel.update()  ──► 책상 먼 모서리 직선 y = a·x + b  (매 프레임 추적)
  │
  ├──► [사용자 펜 분할기] ──► pen_mask (H×W bool)
  │        (검증에서는 demo_pen_segmenter.py 로 대체)
  │
  └──► PenContactDetector.process(frame, pen_mask, table)
          1) pen_geometry: 펜 끝(tip), 축 방향(u), 몸통 굵기(w), w 신뢰도
          2) G  게이트: tip이 먼 모서리보다 아래인가? (d = y_tip − edge_y(x_tip))
          3) 유효성: w 최소값, w 시간 안정성, "책상 아래" 불가능 판정(+tip 연속성)
          4) S  그림자 링: gap / attached / None  (직사광일 때만 자동 활성화)
          5) F  바닥 기하: hover = k − (d + c)/w   [펜 지름 단위]
                 (k, c 는 FloorModel 이 온라인 RANSAC+IRLS 로 자체 추정, S로 부트스트랩)
          6) T  상태기계 AIR ⇄ CONTACT (히스테리시스, 베이스라인, 객체 영속성)
          ──► contact (bool) + 디버그 값
```

연산량(1080p, 2코어 클라우드 컨테이너 CPU, 순수 NumPy/OpenCV): **TableModel ≈ 4.7 ms, ContactDetector ≈ 8.1 ms / frame** (60 fps 예산 16.7 ms 이내). `demo_pen_segmenter`(≈ 56 ms)는 검증용 대체물이며 실제 시스템에서는 사용자의 분할기로 교체된다.

## 3. 모듈 상세

### 3.1 `TableModel` — 책상 먼 모서리 추적 (`table_model.py`)
- **책상 픽셀 판정 `table_like(hsv)`**: 따뜻한 색조(H 4–26) 이면서
  - 밝은 면: S 30–85, V > 150
  - 그림자 면: S 40–140, V 45–150
  → 이 함수가 **유일한 장면 의존 색 상수**. 다른 책상이면 이 함수만 바꾸거나, 사용자의 분할기에 "책상" 클래스가 있으면 그것을 쓰면 된다.
- **열별 모서리 측정**: 0.5배 축소 영상에서 각 열을 아래→위로 스캔해 처음으로 책상이 아닌 행 = 그 열의 모서리.
- **직선 추적**: 책상 먼 모서리는 3D 직선 → 화면 직선. 첫 프레임은 RANSAC, 이후에는 **이전 직선과 ±20 px 이내로 일치하는 열만** 써서 재적합(2단계: 넓게 → ±4 px), EMA(0.3)로 평활. 손·소매가 가린 열은 이전 직선과 불일치하므로 자동 배제된다. 15프레임 연속 실패 시 RANSAC 재시작.
- 이유: 카메라가 천천히 기울어지는 것(관찰 4)을 따라가기 위함. 고정값 대비 이것이 없으면 후반부 d가 수십 px씩 틀어진다.

### 3.2 `pen_geometry(mask)` — 마스크에서 기하량 추출 (`contact_detector.py`)
- **tip**: 마스크 최하단점 주변(반경 260 px) 픽셀로 PCA → 축 `u`(아래 방향). 축 방향 투영 최대값 근처 픽셀 평균 = tip.
- **w (몸통 굵기)**: 해당 영역 마스크의 거리변환 최대값 × 2 = 최대 내접원 지름 → 펜의 원통부 지름(px).
- **w_ok**: 축 방향으로 보이는 길이 ≥ 1.8·w 일 때만 신뢰. (원뿔형 끝부분만 보이면 굵기를 과소추정하므로.)

### 3.3 G — 게이트(하드 제약)
`d = y_tip − edge_y(x_tip) < 4 px` 이면 펜 끝이 책상 먼 모서리보다 위에 찍힌 것 = **물리적으로 책상 위에 있을 수 없음** → 즉시 AIR.
(카메라가 낮으므로 책상 위 수 cm만 떠도 이 선 위로 올라간다. 이것만으로도 "공중" 구간 대부분이 걸러진다.)

### 3.4 F — 바닥 기하(핵심 단서, 자기 보정)

#### 유도
핀홀 카메라, 책상 평면 위 높이 `Hc`, 초점거리 `f`, 펜 지름 `D`, 깊이 `Z`.
- 책상 위 점(높이 0)이 찍히는 행: `y − y_horizon = f·Hc / Z`
- 높이 `h` 인 점: `y − y_horizon = f·(Hc − h) / Z`
- 펜 몸통 화면 굵기: `w = f·D / Z`

`Z`를 소거하면 접촉 시(`h = 0`):
```
y_tip − y_horizon = (Hc / D) · w
```
`y_horizon = edge_y − c` 로 두고 `d = y_tip − edge_y` 를 쓰면
```
접촉:   d = k·w − c          (k = Hc/D, c = 상수)
일반:   hover ≡ h / D = k − (d + c) / w      ← 펜 지름 단위의 떠 있는 높이
```
- `hover = 0` → 접촉, `hover > 0` → 떠 있음, `hover ≪ 0` → 책상 아래(불가능 = 마스크 오류).
- 펜 지름 단위라서 **카메라 거리와 무관한 무차원 임계값**을 쓸 수 있다 (`enter_h = 0.12 D` ≈ 9 mm 펜이면 약 1 mm).
- 닙을 분할기가 포함하든 안 하든 **일관되기만 하면** 닙 길이(지름 대비 상수)는 `k` 에 흡수된다.

#### 온라인 추정 (`FloorModel`) — 라벨 없음
- 버퍼(최근 1800개)에 `(w, d, weight)` 저장. 10프레임마다 재적합.
- **RANSAC**: 2점으로 (k, c) 가설 → 점수 = Σweight·[|잔차| < tol] − Σweight·[잔차 > 2.5·tol] (책상 아래 = 불가능한 점에 벌점). `tol = 0.12·w + 2 px`.
- **IRLS(Tukey biweight)** 로 다듬기: 잔차를 펜 지름 단위로 정규화, MAD 기반 스케일.
- **σ (sigma)**: 적합 후 내점 잔차의 MAD×1.4826 → **"이 분할 품질에서 접촉 프레임의 hover 측정 잡음"을 스스로 추정**. 이후 임계값 일부가 σ에 비례해 자동 조정된다.
- 왜 라벨 없이 되나: 영상에서 접촉 프레임들은 모두 한 직선 위에 모이고, 떠 있는 프레임은 직선의 한쪽(작은 d)으로만 흩어진다. 반대쪽(큰 d)은 물리적으로 불가능 → 직선이 "구조적으로" 정해진다.
- **S로 부트스트랩**: 그림자 단서가 'attached'면 weight 3, 'gap'이면 0.3 → 직선이 접촉 프레임 쪽으로 빨리 수렴.
- 적합 입력은 `w_ok` 인 프레임 전부, **판정**은 추가로 w가 시간적으로 안정된 프레임만(3.6 참고).

테스트 영상에서 자체 추정된 값: `k ≈ 2.52, c ≈ 64.9 px, σ ≈ 0.20 D`.
(참고: 정답 라벨로 최소제곱 적합하면 `k ≈ 2.48, c ≈ 62` → 라벨 없이 거의 같은 직선을 찾음.)

### 3.5 S — 그림자 링 (직사광일 때만)
- **조명 판정** `_lighting_threshold`: 책상 띠의 밝기 히스토그램에 Otsu. 두 모드 각각 3% 이상, 밝은 쪽 평균 ≥ 1.5×어두운 쪽 평균일 때만 "직사광" → 아니면 S 비활성화(확산광에서는 자동으로 꺼짐).
- **링**: 펜 끝부분(축 방향 마지막 0.6 w) 마스크로부터의 거리 `≤ 0.3 w` = near 링, `0.3 w ~ 1.5 w` = far 링. 책상 픽셀(펜 아님, 먼 모서리 아래)만 사용.
- `s_near`, `s_far` = 각 링에서 그림자 픽셀 비율.
  - `s_near < 0.08` 이고 `s_far < 0.5` → **'gap'**: 펜 끝 바로 주변이 전부 밝음 = 펜 끝과 그림자 사이에 빛이 들어옴 = **떠 있음(거부권)**.
  - `s_near > 0.30` 이고 `s_far < 0.20` → **'attached'**: 주변은 밝은데 펜 끝에만 그림자가 붙어 있음 = **접촉 증거**.
  - 그 외(펜 끝이 손 그림자 속에 묻힘 등) → None(정보 없음). **손 그림자 앞에서 떠 있는 경우를 그림자로는 구분할 수 없기 때문**(실험으로 확인, 6.3 참고).

### 3.6 유효성/강건성 장치 (분할 오류 대응)
| 장치 | 내용 | 물리적 근거 |
|---|---|---|
| 최소 굵기 | `w < 20 px` → 무효 | 너무 작은 조각은 펜이 아님 |
| 굵기 시간 안정성 | 최근 4프레임 `max−min ≤ 0.07·median + 3 px` 일 때만 F로 판정 | 굵기는 깊이가 변하는 속도로만 변한다. 빠르게 커지는 굵기 = 펜이 화면에 들어오는 중/분할이 따라오는 중 → 과소추정 |
| 불가능 판정 | `hover < −max(0.6, 5σ)` → 무효(반사상 등) | 펜은 책상 아래로 갈 수 없다 |
| tip 연속성 | 접촉 중이고 tip이 0.6 w 이상 점프하지 않았으면 불가능 판정 생략 | 연속적으로 움직이는 진짜 펜이 "책상 아래"로 읽히면 그것은 직선 모델의 편향(새 깊이 구간)이지 마스크 오류가 아님 |
| 진입 하한 | `h_s > −3σ` 일 때만 F로 진입 | 접촉 측정값은 0 주변 ±σ로 분포. 훨씬 아래는 이상치 |

### 3.7 T — 상태기계 (`PenContactDetector.process`)
평활: `h_s` = 최근 3개 hover의 중앙값 → EMA(0.5).

**AIR → CONTACT**
- (a) 바닥: `−3σ < h_s < enter_h(0.12 D)` 가 2프레임 연속, 'gap' 아님
- (b) 그림자: 'attached' 가 4프레임 연속 (h 모름 또는 `h_s < enter_h + lift_delta`)
- (c) 객체 영속성: 직전 접촉이 **분할 탈락(펜 미검출/무효)** 으로만 끊겼고(들어 올린 증거 없음), 20프레임 이내에, 사라진 위치에서 1 w 이내로 다시 나타나고, gap이 아니며, h가(알 수 있다면) 그때 베이스라인 + 0.2 D 이내 → 2프레임

**CONTACT → AIR**
- G 실패 → **즉시**
- 펜 무효/미검출, 'gap', 또는 **LIFT**: `h_s − base > lift_delta` ('attached'가 아닐 때) 가 2프레임 연속
  - `lift_delta = max(0.25, 1.5σ)` (≈ 0.30 D in test)
  - `base`(베이스라인): 접촉 진입 시 `h_s`, 이후 접촉 중 EMA(0.1)로 천천히 추종 → 펜을 미끄러뜨리거나 기울일 때 생기는 **느린 편향은 흡수**, 실제로 들어 올릴 때의 **빠른 상승만 반응**.

출력 dict: `contact, hover(원시), h_s(평활), base, lift_delta, shadow, s_near, s_far, tip, w, d, reason`.

### 4.3 기여도 분석 (`python ablation.py`)
| 구성 | 정확도 | 정밀도 | 재현율 | 정확도(저신뢰 제외) |
|---|---|---|---|---|
| 순진한 방법: 끝이 모서리 아래면 접촉 | 0.828 | 0.754 | 0.981 | 0.815 |
| G + S(그림자만) | 0.930 | 0.935 | 0.926 | 0.925 |
| G + F(바닥 기하만) | 0.833 | 0.888 | 0.766 | 0.876 |
| G + F + S | 0.914 | 0.992 | 0.837 | 0.974 |
| **전체(G+F+S+객체 영속성)** | **0.927** | **0.993** | 0.862 | **0.988** |

해석: 이 영상은 햇빛이 강해 S 단독도 강하지만, S만으로는 **손 그림자 앞 호버**를 접촉으로 오판(정밀도 0.935). F를 더하면 그 오판이 사라지고(정밀도 0.99), 객체 영속성이 분할 탈락으로 인한 끊김을 메운다.

## 6. 한계와 솔직한 평가

### 6.1 과적합 위험
임계값들은 물리적 의미(펜 지름 단위, σ 배수)로 정했지만 **설계 반복 과정에서 이 영상 하나를 보며 조정했다**. 따라서 위 수치는 낙관적일 수 있다. **다른 영상(다른 조명, 각도, 펜, 사람)으로 반드시 재검증**해야 한다. 특히 `enter_h=0.12`, `lift_sigmas=1.5`, `n_on/n_off`, 그림자 링 임계값(0.08/0.30/0.20/0.5).

### 6.2 검증용 분할기의 한계가 결과를 지배
`demo_pen_segmenter.py`는 색(파랑–빨강 크로마) 기반의 임시 분할기다. 닙/아랫면 누락, 굵기 측정 잡음, 반사상 오검출, 일부 프레임 탈락이 있다. 이 때문에 F의 잡음 σ ≈ 0.20 D (9 mm 펜이면 약 ±1.8 mm). **실제 분할기가 더 정확하면 σ가 줄고, 임계값이 σ에 비례하므로 더 낮은 호버도 구분 가능**해진다.

### 6.3 남은 실패 유형
1. **거의 수직인 펜 + 손 그림자 속 끝(262–305)**: 측정된 hover가 0.15–0.3 D로 실제 호버 구간(330–352, 0.2–0.35 D)과 겹친다. 이 분할 품질로는 원리적으로 분리 불가. 정밀한 tip/굵기 측정이 필요.
2. **바닥 직선의 비선형성**: 먼 쪽(w ≈ 35–45 px)에서 직선이 접촉을 −0.5 ~ −1 D로 읽는다. tip 연속성 규칙으로 버티지만, 근본적으로는 tip 정의의 자세 의존 편향 때문. (개선안: w 구간별 비모수 상한선(isotonic) 또는 2차 항.)
3. **분할 탈락**: 펜이 수 프레임 사라지면 접촉이 잠시 끊긴다(551–555). 객체 영속성은 20프레임 이내 재등장만 메운다.

### 6.4 시도했다가 버린 것 (다음 작업자를 위한 기록)
| 시도 | 결과/버린 이유 |
|---|---|
| HSV 임계 분할 | 데님 재킷·꽃병·반사상과 혼동, 펜 아랫면(따뜻한 반사광)·닙 누락 |
| GrabCut 보정 | 그림자/옷으로 번짐, 570 ms/frame |
| 펜 끝 바로 아래 "접촉 그림자 초승달" 어둡기 | 손 그림자 앞 호버와 값이 같음(0.21–0.28 vs 0.22–0.30) → AUC≈0.6 |
| 펜 끝 링 그림자 비율만으로 접촉 판정 | 손 그림자 앞 호버에서 s_near 0.6 → 오판. 그래서 'gap'(거부권)과 'attached'(주변이 밝을 때만) 둘로 제한 |
| FloorModel에서 '불가능 점' 강한 벌점(상한 포락선) | 잡음 쪽 극단에 직선이 붙어 접촉이 0.2–0.4 D 떠 있는 것으로 편향 → 벌점 완화 + IRLS |
| 로지스틱 증거 합산 + 확률 히스테리시스 | 단서가 엇갈릴 때 0.5 근처에 붙어 상태가 고착 → hover 공간의 상태기계로 교체 |
| 절대 hover 임계로 이탈 판정 | 미끄러질 때 자세 편향(0.2–0.6 D)으로 끊김 → 접촉 베이스라인 대비 상대 상승으로 변경 |
| 오디오(펜 소리) | 주변 소음에 묻혀 검출 불가(그리고 요구사항상 영상만 사용) |

### 6.5 개선 아이디어 (라벨·하드웨어 없이 가능한 것)
- **tip 정밀화**: 원뿔 끝의 두 옆선을 직선 적합해 꼭짓점을 외삽 → 닙 보임 여부와 무관한 일관된 tip.
- **굵기 정밀화**: 몸통 양쪽 윤곽을 서브픽셀로 직선 적합, 축에 수직인 폭의 중앙값.
- **반사상 단서**: 광택 책상에서 그늘 영역의 펜 반사상은 책상 면에 대해 거울 대칭 → 펜 끝과 반사상 끝 사이 간격 = 2h. 그늘에서 S가 무력한 바로 그 상황을 보완할 수 있다.
- **바닥 모델 확장**: `d = k·w − c` 에 x 의존 항(카메라 롤/렌즈 왜곡), 혹은 w 구간별 상한선.
- **자기 지도 미세조정**: 이 파이프라인이 고신뢰로 내린 판정(예: G로 확실한 공중, F+S가 모두 동의한 접촉)을 의사 라벨로 써서 펜 끝 패치 분류기를 온라인으로 학습(사람 라벨 없음).
